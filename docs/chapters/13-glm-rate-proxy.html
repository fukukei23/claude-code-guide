概要：なぜプロキシが必要か

Claude Codeは通常、Anthropic APIに直接接続する。しかし ANTHROPIC_BASE_URL を差し替えることで、Anthropic互換APIを持つ別プロバイダに向けられる。

graph LR A[Claude Code CLI] --> B[localhost:8787
glm-rate-proxy] B --> C[api.z.ai
GLM-5.1] B --> D[api.minimax.io
MiniMax フォールバック] style B fill:#f5a623,color:#000 style C fill:#4a90d9,color:#fff style D fill:#7ed321,color:#000

コスト比較

Claude Max $200/月（サブスク）ZAI GLM（従量）
月間トークン上限約3,000〜3,200万トークン制限なし（従量課金）
$200換算約3,700万トークン相当数十億トークン規模
コスパ差ベースライン約77〜190倍
体感との乖離について
計算上は90〜190倍の差があるが、GLM-5.1はThinking（内部推論）トークンを大量消費するため、実用上の差は2〜3倍程度に感じることが多い。Thinking制御が重要な理由はここにある。

ファイル構成

~/.claude/scripts/glm-rate-proxy/
├── src/glm_rate_proxy/

モデルルーティング

使用量（usage_pct）とピーク時間帯に応じて自動でモデルが切り替わる。

モード条件使用モデルプロバイダ
normalusage < 80%GLM-5.1ZAI
economy80% ≤ usage < 95%GLM-4.7ZAI
emergencyusage ≥ 95%GLM-4.7-FlashZAI
peak_blockJST 15:00〜19:00MiniMax-M2.7MiniMax
ピーク時間帯の理由
ZAI公式ドキュメントによるとGLM-5.1はピーク時に3倍の消費レートで計算される。MiniMaxに逃がすことでZAIクォータを温存する。

Thinkingモードの動的制御

GLM-5.1はデフォルトで「思考モード」が有効で、内部推論トークンを大量消費する。

問題：思考トークンの暴走

  • 「このファイルも確認が必要」という1行のために 16,000トークンの内部思考を消費した事例あり
  • 平均LLMと比較して 2.6倍の冗長さ（Artificial Analysis実測）
  • 暴走すると10〜15分のハング状態になることもある

解決策：キーワードベースの動的切り替え

プロキシがリクエストのメッセージ内容を検査して自動判断する。

graph TD A[リクエスト受信] --> B{thinking.mode?} B -->|always_off| C["thinking: disabled"] B -->|always_on| D["thinking: enabled
budget: 8,000"] B -->|auto| E{キーワード検出?} E -->|edit/fix/implement/
debug/write/refactor/
create/add/modify/
update/build/test/generate| D E -->|その他| C

budget_tokensについて

値特徴
1,024（最小）ZAI APIの最小値。これ以下はエラー
8,000（デフォルト）暴走報告(16k)の半分。安全マージンあり
16,000暴走事例と同水準。リスク高
上限なし（enabled）モデル自動判断。暴走リスク最大
budget_tokens は上限であり、モデルが必ず使い切るわけではない。 ただしGLM-5.1が上限を厳守するかは未検証のため、低めに設定しておくことを推奨。

設定の変更

config/config.json の thinking セクションを編集してプロキシを再起動：

{
  "thinking": {
    "mode": "auto",        // "auto" | "always_on" | "always_off"
    "budget_tokens": 8000
  }
}

ステータス確認

curl -s http://127.0.0.1:8787/proxy/status | python3 -m json.tool
{
  "usage_pct": 23.5,
  "request_count": 1016,
  "mode": "normal",
  "provider": "zai",
  "peak_block": false,
  "last_actual_model": "glm-5.1"
}
フィールド意味
usage_pctZAIの月間クォータ消費率（%）
mode現在のルーティングモード（normal/economy/emergency/peak_block）
provider次のリクエストの送信先
peak_blockピーク時間帯ブロック中かどうか
last_actual_model直近リクエストで実際に使われたモデル

起動・停止

# 起動（SessionStart hookで自動実行されるが、手動でも可）
bash ~/.claude/scripts/llm/start-glm-proxy.sh

# プロセス確認
pgrep -a -f glm_rate_proxy

# 停止
pkill -f glm_rate_proxy

# ログ確認
tail -f /tmp/glm-proxy.log

# ピークブロックを一時的に無効化して起動
GLM_PEAK_BLOCK=false bash ~/.claude/scripts/llm/start-glm-proxy.sh

トラブルシューティング

❌ Claude Codeが「API error」を返す

# 1. プロキシが起動しているか確認
pgrep -a -f glm_rate_proxy

# 2. ポートが開いているか確認
curl -s http://127.0.0.1:8787/proxy/status

# 3. 再起動
pkill -f glm_rate_proxy
bash ~/.claude/scripts/llm/start-glm-proxy.sh

❌ 応答が遅い・ハングする（10分以上）

Thinkingモードが暴走している可能性が高い。

# 応急処置：Thinkingを全OFFにして再起動
# config/config.json の thinking.mode を "always_off" に変更後：
pkill -f glm_rate_proxy
bash ~/.claude/scripts/llm/start-glm-proxy.sh

❌ レート制限（429）が頻発する

# 使用量を確認
curl -s http://127.0.0.1:8787/proxy/status | python3 -c \
  "import json,sys; d=json.load(sys.stdin); print(f\"usage: {d['usage_pct']}% | mode: {d['mode']}\")"

usage_pctが95%超でもMiniMaxフォールバックが機能しない場合は、last_actual_model を確認。

強制的にMiniMaxに切り替える方法： config.jsonのpeak_hours.start_hourを0、end_hourを24に設定（24時間ピーク扱い）。

❌ No module named glm_rate_proxy

# PYTHONPATHを明示して起動
cd ~/.claude/scripts/glm-rate-proxy
PYTHONPATH=src python3 -m glm_rate_proxy

❌ Thinking ONなのに効果が感じられない

ZAIの enabled モードはモデルが自動判断して思考量を決める。効果を強制したい場合：

// config.json
{
  "thinking": {
    "mode": "always_on",
    "budget_tokens": 12000
  }
}
budget_tokensを16,000以上にすると暴走リスクが高まる。

設定リファレンス（config.json 全項目）

{
  "zai_base_url": "https://api.z.ai/api/anthropic",
  "minimax_base_url": "https://api.minimax.io/anthropic/v1",
  "listen_host": "127.0.0.1",
  "listen_port": 8787,
  "upstream_timeout": 1200,
  "log_level": "INFO",          // "DEBUG" にするとthinking判定ログが出る
  "default_model": "GLM-5.1",
  "thresholds": {
    "normal":    {"max_pct": 80,  "model": null},
    "economy":   {"max_pct": 95,  "model": "GLM-4.7"},
    "emergency": {"max_pct": 100, "model": "GLM-4.7-Flash"}
  },
  "fallback": {
    "provider": "minimax",
    "model": "MiniMax-M2.7"
  },
  "peak_hours": {
    "enabled": true,
    "start_hour": 15,
    "end_hour": 19,
    "timezone_offset": 9        // JSTの場合 9
  },
  "thinking": {
    "mode": "auto",             // "auto" | "always_on" | "always_off"
    "budget_tokens": 8000,
    "coding_keywords": [
      "edit", "fix", "implement", "debug", "write", "refactor",
      "create", "add", "modify", "update", "build", "test", "generate"
    ]
  }
}
