05 フック — イベント駆動の自動実行

フックとは

フックは 特定のイベント発生時に自動実行されるシェルスクリプト。Claude Codeの動作を拡張・制御する。

ユーザーがツールを実行
  │
  ▼
PreToolUse フックが発火 ──→ チェックOK → ツール実行
  │                          └─ チェックNG → ブロック
  ▼
ツールが実行される
  │
  ▼
PostToolUse フックが発火 ──→ ログ記録・後処理
sequenceDiagram participant U as ユーザー participant CC as Claude Code participant Pre as PreToolUse participant Tool as ツール participant Post as PostToolUse Note over CC: 🔄 SessionStart Hook発火 U->>CC: リクエスト送信 CC->>Pre: ツール実行前チェック alt チェックOK Pre->>Tool: ✅ ツール実行 Tool->>Post: 実行完了 Post->>CC: ログ記録 else チェックNG Pre-->>CC: 🚫 ブロック end CC->>U: レスポンス Note over CC: 🔄 Stop Hook発火

4種のフック

SessionStart

セッション開始時に実行。

項目 説明
タイミング Claude Code起動時
用途 環境変数の読み込み（~/.secrets.env）、SSOT日記・バックログの読込、設定の検証
備考 最後に startup-banner.sh が全フックのステータス＋スキルトリガーマップを集約してバナー表示

PreToolUse

ツール実行前に実行。最も重要なフック。

項目 説明
タイミング 各ツール（Read, Edit, Bash等）の実行前
用途 セキュリティチェック、危険コマンドのブロック、入力検証
備考 なし
ブロック可能 Yes — スクリプトがエラーを返すとツール実行がキャンセルされる

現場の知見: フックのスクリプトがエラー（exit code ≠ 0）を返すと、ツールの実行がサイレントにブロックされる。意図せぬブロックに注意。→ 11_現場の知見

ブロックされるコマンドの例:

  • bash -x（デバッグ出力でシークレット露出の恐れ）
  • cat -A（特殊文字表示でシークレット露出の恐れ）
  • マスクなしの grep（APIキーを含むファイルの検索）
  • フィルタなしの env（全環境変数の表示）

PostToolUse

ツール実行後に実行。

項目 説明
タイミング 各ツールの実行後
用途 ログ記録、実行結果の後処理、通知
備考 なし

Stop

セッション終了時に実行。

項目 説明
タイミング Claude Code終了時
用途 クリーンアップ、ログ保存、ハンドオフ情報の書き出し
備考 なし

設定方法

フックは settings.json の hooks セクションに定義する。

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 ~/.claude/scripts/security/check-command-safety.py"
          }
        ]
      }
    ],
    "SessionStart": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "source ~/.secrets.env"
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/scripts/session/save-session-log.sh",
            "timeout": 5000
          },
          {
            "type": "command",
            "command": "~/.claude/scripts/session/generate-handoff.sh",
            "timeout": 3000
          },
          {
            "type": "command",
            "command": "~/.claude/scripts/session/queue-guide-updates.sh",
            "timeout": 5000
          }
        ]
      }
    ]
  }
}

matcherについて

  • matcher はツール名を指定（例: "Bash", "Edit", "Read"）
  • 空文字 "" は全ツールにマッチ
  • 複数のフックを設定可能（配列で定義）

デバッグ方法

フックが期待通りに動かない場合:

  1. フックのログを確認 — エラーメッセージが表示される
  2. 手動でスクリプトを実行 — ターミナルで直接実行して動作確認
  3. /config で設定確認 — hooks セクションの内容を確認
  4. 一時的に無効化 — settings.json で該当フックをコメントアウト

トラブルシューティング

Windows + WSL環境でPreToolUseフックがエラーになる

症状: PreToolUseフック（check-command-safety.py 等）が Windows 側で実行され、python3: command not found 等のエラーになる。

原因: Windows側のシェルが ~/.claude/scripts/... というUnixパスをWindowsパスとして解釈しようとする。フックスクリプトで python3 を直接呼ぶと、Windows Git Bash環境では動作しない。

解決策: run-security-check.sh のようなラッパースクリプト（python3 / python / wsl を自動検出）経由で呼ぶ。Cron等の自動実行でも wsl bash -c "..." 経由で呼ぶことで、Windows側のシェルがパスを解釈する前にWSL側に処理が渡される。
